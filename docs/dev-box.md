# Backstage Dev Box (EC2)

The Backstage instance runs on EC2 (it needs a Unix-like OS + GNU toolchain;
Windows has neither). It never talks to the kind cluster: Backstage -> GitHub
API -> ArgoCD pulls -> kind. So no VPN/tunnel to the laptop is needed.

## 1. Apply (budget + EC2 together)

From `bootstrap/terraform`:

```powershell
terraform apply
```

Review the plan — it creates:

- `aws_budgets_budget.tarmac` ($50/mo alerts to rajvasoya06@gmail.com)
- `aws_security_group.backstage_dev` (SSH only from operator IP)
- `aws_instance.backstage_dev` (m7i-flex.large, Ubuntu 24.04, 30GB gp3 encrypted,
  user_data scripts Node 22/Docker/swap)

Type `yes`. Note: the old `budget.tfplan` is stale — ignore it, run a fresh
`apply`.

## 2. Get the box's info

```powershell
terraform output -raw dev_public_ip
terraform output dev_ssh
```

Public IP changes each start (no EIP on purpose — saves money while stopped).
Verify the real IP via `aws ec2 describe-instances --instance-ids <id>`
(terraform output can be stale after a restart).

## 3. First SSH + verify cloud-init finished

```powershell
ssh -i "D:\DevOps\Projects\Tarmac\bootstrap\terraform\tarmac-dev.pem" ubuntu@<IP>
sudo tail -f /var/log/cloud-init-output.log
```

Wait until you see the `.cloud-init-done` marker / prompt returns. Verify:
`node -v` -> v22.x, `corepack --version`, `pnpm --version` (portal is pnpm,
not yarn), `docker ps` works.

## 4. Start the portal (on the box)

The portal lives at `~/tarmac/portal` (clone of the tarmac monorepo).

```bash
cd ~/tarmac/portal
git pull                      # get latest template/template.yaml changes
pkill -f '[b]ackstage-cli repo start'; pkill -f '[r]spack'   # stop old (bracket trick avoids self-kill)
nohup pnpm start > /tmp/portal.log 2>&1 &                    # use `start`, NOT `dev`
```

Verify: `curl -s -o /dev/null -w '%{http_code}' http://localhost:3000/` -> 200,
and the log shows `Plugin initialization complete`.

Secrets live only at `~/secrets/` on the box (GitHub App private key +
client secret). `app-config.local.yaml` (gitignored) is regenerated by
`~/gen-config.py` and inlines them via env vars. Never commit secrets.

## 5. Tunnel to your browser (on your PC)

```powershell
ssh -i "D:\DevOps\Projects\Tarmac\bootstrap\terraform\tarmac-dev.pem" -N -L 3000:localhost:3000 -L 7007:localhost:7007 ubuntu@<IP>
```

Then `http://localhost:3000` (Backstage UI) in your browser.

## 6. Local kind cluster + ArgoCD (on the PC, not the box)

The kind cluster (`tarmac`) runs on the laptop. ArgoCD lives in the `argocd`
namespace. The root app `tarmac-config` watches `clusters/local` in the
tarmac-config repo and auto-applies every YAML there (incl. new service
Application manifests merged via scaffolder PRs).

**ArgoCD repo access via GitHub App (applied once):** ArgoCD connects to all
`tarmac-platform` repos through a `repo-creds` credential template backed by
the `tarmac-backstage` GitHub App (id 4584825, installation 153530788). This
was applied by hand on the cluster:

```bash
kubectl apply -f - <<'EOF'
apiVersion: v1
kind: Secret
metadata:
  name: github-app-creds
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: repo-creds
stringData:
  type: git
  url: https://github.com/tarmac-platform
  githubAppID: "4584825"
  githubAppInstallationID: "153530788"
  githubAppPrivateKey: |
    <contents of ~/secrets/tarmac-backstage.pem>
EOF
```

The private key is NOT in git (gitignored, `*.pem`); re-apply this secret
manually after any cluster rebuild.

## 7. Stop the box when done (keep EBS, stop billing)

```powershell
aws ec2 stop-instances --instance-ids <instance-id>
```

Restart next day, note the new public IP, re-open the tunnel.
